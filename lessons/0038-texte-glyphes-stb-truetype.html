Leçon 38 · Moteur de paroles en C++ (2/N)

Du pixel au glyphe : le premier vrai texte

La Leçon 37 a prouvé que le buffer C++ arrive intact à l'écran — avec un dégradé et un damier, rien de lisible. Cette leçon fait apparaître du vrai texte, dessiné lettre par lettre en C++ pur, via stb_truetype (bibliothèque à un seul fichier, domaine public/MIT). Toujours minimal : une chaîne fixe ("Karamock"), pas encore les paroles réelles ni plusieurs lignes — ça viendra une fois ce mécanisme prouvé.

stb_truetype : une bibliothèque, un seul fichier, une discipline à respecter

Premier piège, avant même la licence : nothings/stb n'est pas un dépôt dédié à une seule bibliothèque. C'est un seul repo qui en contient une vingtaine (stb_image.h, stb_vorbis.c, stb_truetype.h, stb_easy_font.h...), toutes posées en vrac à la racine, sans sous-dossier par bibliothèque ni release packagée à télécharger. C'est précisément pour ça que le README ne donne aucune instruction d'intégration spécifique — chaque fichier est auto-documenté, le bloc USAGE en tête de fichier (cité plus bas) en tient lieu.

Ce qu'il faut récupérer : un seul fichier, stb_truetype.h — rien d'autre du repo, pas de clone, pas de gestionnaire de paquets. Deux façons de l'obtenir :

  1. Le fichier brut directement : https://raw.githubusercontent.com/nothings/stb/master/stb_truetype.h — ouvrir l'URL, Cmd+S pour l'enregistrer.
  2. Depuis l'interface GitHub : ouvrir github.com/nothings/stb, cliquer sur stb_truetype.h dans la liste de fichiers, puis sur le bouton "Raw" en haut à droite du fichier affiché, puis Cmd+S.

Le fichier obtenu, glisse-le dans Xcode, dans le dossier Engine/ThirdParty/, cible Karamock cochée. Aucune configuration de build supplémentaire n'est nécessaire pour ce .h en lui-même — seul stb_truetype_impl.cpp (créé plus bas, avec la macro) a besoin d'être compilé.

stb_truetype.h est publié sous double licence, au choix du destinataire — le fichier source le dit lui-même, en toutes lettres :

"This software is available under 2 licenses -- choose whichever you prefer. ALTERNATIVE A - MIT License [...] ALTERNATIVE B - Public Domain (www.unlicense.org)"

Redistribution en app (App Store compris) sans restriction. Le fichier porte aussi un avertissement à prendre au sérieux plutôt qu'à ignorer :

"NO SECURITY GUARANTEE -- DO NOT USE THIS ON UNTRUSTED FONT FILES. This library does no range checking of the offsets found in the file, meaning an attacker can use it to read arbitrary memory."

Sans conséquence ici : Karamock n'embarque jamais qu'une police choisie par le projet lui-même, jamais un fichier fourni par l'utilisateur ou téléchargé au runtime.

C'est une bibliothèque "à un seul header" — tout le code est dans stb_truetype.h, activé par une macro qu'il faut poser avec discipline. Le fichier le documente ainsi :

"Include this file in whatever places need to refer to it. In ONE C/C++ file, write: #define STB_TRUETYPE_IMPLEMENTATION before the #include of this file."

Deux erreurs symétriques si cette règle n'est pas respectée à la lettre :

ErreurSymptôme au lien
La macro n'est définie dans aucun fichierUndefined symbols for architecture arm64: "_stbtt_InitFont" — seuls les prototypes existent
La macro est définie dans deux fichiers ou plusduplicate symbol '_stbtt_InitFont' — le corps des fonctions est émis deux fois
// NOUVEAU — Engine/ThirdParty/stb_truetype_impl.cpp
// Le seul fichier du projet à définir cette macro. Rien d'autre ici.
#define STB_TRUETYPE_IMPLEMENTATION
#include "stb_truetype.h"

Autre règle propre à ce projet, pas à stb_truetype en général : stb_truetype.h ne doit jamais apparaître dans un en-tête ajouté au bridging header. stbtt_fontinfo est une struct C avec des champs internes que Swift n'a aucune raison de voir — le garder entièrement derrière un pimpl, comme la section suivante le montre, évite à Swift d'avoir à l'importer.

PixelBuffer apprend à dessiner

Jusqu'ici PixelBuffer n'exposait que de la lecture. Il gagne une écriture encapsulée plutôt qu'un pointeur mutable brut — le clipping et le mélange alpha restent à un seul endroit, jamais dupliqués ailleurs dans le moteur :

// CORRECTION — Engine/PixelBuffer.hpp (ajouts)
void fill(std::uint8_t r, std::uint8_t g, std::uint8_t b);
void blendPixel(int x, int y,
                 std::uint8_t r, std::uint8_t g, std::uint8_t b,
                 std::uint8_t coverage);   // no-op si (x, y) est hors des bornes du buffer
// CORRECTION — Engine/PixelBuffer.cpp (ajouts)
void PixelBuffer::fill(std::uint8_t r, std::uint8_t g, std::uint8_t b) {
    for (int y = 0; y < height_; ++y) {
        for (int x = 0; x < width_; ++x) {
            const std::size_t i = (static_cast<std::size_t>(y) * width_ + x) * 4;
            pixels_[i + 0] = r;
            pixels_[i + 1] = g;
            pixels_[i + 2] = b;
            pixels_[i + 3] = 255;
        }
    }
}

void PixelBuffer::blendPixel(int x, int y, std::uint8_t r, std::uint8_t g, std::uint8_t b, std::uint8_t coverage) {
    if (x < 0 || y < 0 || x >= width_ || y >= height_) {
        return;
    }
    const std::size_t i = (static_cast<std::size_t>(y) * width_ + x) * 4;
    const int inv = 255 - coverage;
    pixels_[i + 0] = static_cast<std::uint8_t>((r * coverage + pixels_[i + 0] * inv + 127) / 255);
    pixels_[i + 1] = static_cast<std::uint8_t>((g * coverage + pixels_[i + 1] * inv + 127) / 255);
    pixels_[i + 2] = static_cast<std::uint8_t>((b * coverage + pixels_[i + 2] * inv + 127) / 255);
    // alpha reste à 255 : le fond de ce buffer est toujours opaque
}

+ 127 avant la division par 255 arrondit au plus proche plutôt que de tronquer — sans lui, le texte "maigrit" visiblement sur les bords antialiasés, un défaut réel mais facile à ne jamais remarquer si on ne sait pas qu'il faut le chercher.

Font : les octets et la police doivent vivre ensemble

Point vérifié précisément dans le code source de stb_truetype, parce que c'est le piège central de cette leçon : stbtt_InitFont ne copie rien depuis le fichier .ttf, il pointe dedans.

""Load" a font file from a memory buffer (you have to keep the buffer loaded)"

Si le tableau d'octets du .ttf est détruit ou déplacé pendant que stbtt_fontinfo existe encore, chaque appel suivant lit de la mémoire invalide — silencieusement, jusqu'au crash aléatoire. La structure Font matérialise cette contrainte en gardant les octets et la stbtt_fontinfo dans le même objet, et en interdisant la copie :

// NOUVEAU — Engine/Font.hpp — aucun #include de stb_truetype.h ici
#pragma once
#include <cstdint>
#include <memory>
#include <vector>

namespace karamock {

class Font {
public:
    Font();
    ~Font();                          // définie dans le .cpp — obligatoire pour le pimpl
    Font(Font&&) noexcept;
    Font& operator=(Font&&) noexcept;
    Font(const Font&) = delete;       // move-only : jamais deux Font pointant vers les mêmes octets
    Font& operator=(const Font&) = delete;

    bool loadFromMemory(std::vector<std::uint8_t> ttfBytes);   // prend possession des octets
    bool loadFromMemory(const std::uint8_t* bytes, std::size_t count);   // copie count octets, délègue à la version au-dessus
    bool isValid() const;

    float scaleForPixelsHeight(float pixelHeight) const;
    void verticalMetrics(int* ascent, int* descent, int* lineGap) const;

private:
    const void* nativeHandle() const; // réservé à TextRenderer — voir explication ci-dessous

    struct Impl;                      // contient les octets ET stbtt_fontinfo, ensemble
    std::unique_ptr<Impl> impl_;
    friend class TextRenderer;
};

} // namespace karamock
// NOUVEAU — Engine/Font.cpp
#include "Font.hpp"
#include "stb_truetype.h"

namespace karamock {

struct Font::Impl {
    std::vector<std::uint8_t> ttf;   // déclaré AVANT info : doit survivre à info
    stbtt_fontinfo info{};
    bool valid = false;
};

Font::Font() : impl_(std::make_unique<Impl>()) {}
Font::~Font() = default;
Font::Font(Font&&) noexcept = default;
Font& Font::operator=(Font&&) noexcept = default;

bool Font::loadFromMemory(std::vector<std::uint8_t> ttfBytes) {
    impl_->ttf = std::move(ttfBytes);
    const int offset = stbtt_GetFontOffsetForIndex(impl_->ttf.data(), 0);
    impl_->valid = offset >= 0 && stbtt_InitFont(&impl_->info, impl_->ttf.data(), offset) != 0;
    return impl_->valid;
}

bool Font::loadFromMemory(const std::uint8_t* bytes, std::size_t count) {
    if (!bytes || count == 0) {
        impl_->valid = false;
        return false;
    }
    std::vector<std::uint8_t> ttfBytes(bytes, bytes + count);   // une seule copie, ici
    return loadFromMemory(std::move(ttfBytes));
}

bool Font::isValid() const { return impl_->valid; }

float Font::scaleForPixelsHeight(float pixelHeight) const {
    return stbtt_ScaleForPixelHeight(&impl_->info, pixelHeight);
}

void Font::verticalMetrics(int* ascent, int* descent, int* lineGap) const {
    stbtt_GetFontVMetrics(&impl_->info, ascent, descent, lineGap);
}

const void* Font::nativeHandle() const {
    return &impl_->info;
}

} // namespace karamock

Pourquoi nativeHandle() est nécessaire, et pas seulement friend class TextRenderer seul : Font.hpp ne déclare struct Impl; qu'en type incomplet — sa définition complète (avec le champ info) n'existe que dans Font.cpp. La déclaration d'amitié donne à TextRenderer la permission d'accéder aux membres privés de Font, mais ne rend pas Impl complet pour autant : TextRenderer.cpp, qui ne voit jamais la définition de Impl, ne pourrait pas écrire font.impl_->info même en étant ami — le compilateur refuserait de déréférencer un type dont il ne connaît pas la taille ni les membres. nativeHandle() contourne ça proprement : elle retourne un const void* (un type toujours complet, quelle que soit son origine), calculé à l'intérieur de Font.cpp où Impl est complet, et TextRenderer.cpp n'a plus qu'à le re-caster vers const stbtt_fontinfo* — un type qu'il connaît déjà, puisqu'il inclut lui-même stb_truetype.h.

Cette même logique interdit toujours d'inclure stb_truetype.h dans Font.hpp — le type stbtt_fontinfo n'a besoin d'être connu que là où il est réellement manipulé (Font.cpp et TextRenderer.cpp), jamais dans un en-tête ajouté au bridging header.

Impl::ttf déclaré avant Impl::info : les membres d'une struct C++ sont détruits dans l'ordre inverse de leur déclaration, donc info (qui pointe dans ttf) est détruit avant ttf — l'ordre inverse serait une destruction qui invaliderait un pointeur encore référencé l'instant d'avant. ~Font() définie dans le .cpp plutôt que = default dans le header : nécessaire pour l'idiome pimpl, parce que std::unique_ptr<Impl> doit connaître la taille complète de Impl au moment où le destructeur est généré, ce qui n'est possible que là où Impl est entièrement défini.

TextRenderer : la boucle glyphe par glyphe

stb_truetype rasterise en niveaux de gris 8 bits — un octet de couverture par pixel (0 = transparent, 255 = plein), pas une couleur. Le fichier source le dit explicitement, et prévient d'un piège que la leçon doit respecter à la lettre :

"note that this stomps the old data [...] if you want to render a sequence of characters, you really need to render each bitmap to a temp buffer, then 'alpha blend' that into the working buffer"

stbtt_MakeCodepointBitmap écrase ce qu'il y a dans le buffer qu'on lui passe, il ne mélange jamais. Rastériser directement dans PixelBuffer serait donc doublement faux : mauvais format (1 octet/pixel contre 4) et destruction du fond déjà dessiné. La bonne séquence : un petit buffer 8 bits temporaire par glyphe, puis blendPixel pixel par pixel dans le vrai buffer.

// NOUVEAU — Engine/TextRenderer.hpp
#pragma once
#include <cstdint>
#include <string>
#include <vector>

namespace karamock {

class Font;
class PixelBuffer;

struct Color { std::uint8_t r, g, b; };

class TextRenderer {
public:
    void drawText(PixelBuffer& target, const Font& font, const std::string& text,
                  int x, int baselineY, float pixelHeight, Color color);

    int measureWidth(const Font& font, const std::string& text, float pixelHeight) const;

private:
    std::vector<std::uint8_t> glyphScratch_;   // buffer 8 bits réutilisé, remis à zéro à chaque glyphe
};

} // namespace karamock
// NOUVEAU — Engine/TextRenderer.cpp (fichier complet)
#include "TextRenderer.hpp"
#include "Font.hpp"
#include "PixelBuffer.hpp"
#include "stb_truetype.h"

namespace karamock {

void TextRenderer::drawText(PixelBuffer& target, const Font& font, const std::string& text,
                             int x, int baselineY, float pixelHeight, Color color) {
    if (!font.isValid()) {
        return;
    }
    const stbtt_fontinfo* fontInfo = static_cast<const stbtt_fontinfo*>(font.nativeHandle());
    const float scale = font.scaleForPixelsHeight(pixelHeight);
    float xpos = static_cast<float>(x);

    for (std::size_t k = 0; k < text.size(); ++k) {
        const int c = static_cast<unsigned char>(text[k]);

        int advance = 0, leftBearing = 0;
        stbtt_GetCodepointHMetrics(fontInfo, c, &advance, &leftBearing);

        int ix0, iy0, ix1, iy1;
        stbtt_GetCodepointBitmapBox(fontInfo, c, scale, scale, &ix0, &iy0, &ix1, &iy1);
        const int w = ix1 - ix0;
        const int h = iy1 - iy0;

        if (w > 0 && h > 0) {                                        // ' ' donne w == 0 : rien à dessiner
            glyphScratch_.assign(static_cast<std::size_t>(w) * h, 0);   // reset — sinon glyphe "fantôme"
            stbtt_MakeCodepointBitmap(fontInfo, glyphScratch_.data(), w, h, /*stride*/ w, scale, scale, c);

            for (int gy = 0; gy < h; ++gy) {
                for (int gx = 0; gx < w; ++gx) {
                    const std::uint8_t coverage = glyphScratch_[static_cast<std::size_t>(gy) * w + gx];
                    if (coverage != 0) {
                        target.blendPixel(static_cast<int>(xpos) + ix0 + gx, baselineY + iy0 + gy,
                                           color.r, color.g, color.b, coverage);
                    }
                }
            }
        }

        xpos += advance * scale;
        if (k + 1 < text.size()) {
            xpos += scale * stbtt_GetCodepointKernAdvance(fontInfo, c, static_cast<unsigned char>(text[k + 1]));
        }
    }
}

int TextRenderer::measureWidth(const Font& font, const std::string& text, float pixelHeight) const {
    if (!font.isValid()) {
        return 0;
    }
    const stbtt_fontinfo* fontInfo = static_cast<const stbtt_fontinfo*>(font.nativeHandle());
    const float scale = font.scaleForPixelsHeight(pixelHeight);
    float width = 0.0f;

    for (std::size_t k = 0; k < text.size(); ++k) {
        const int c = static_cast<unsigned char>(text[k]);
        int advance = 0, leftBearing = 0;
        stbtt_GetCodepointHMetrics(fontInfo, c, &advance, &leftBearing);
        width += advance * scale;
        if (k + 1 < text.size()) {
            width += scale * stbtt_GetCodepointKernAdvance(fontInfo, c, static_cast<unsigned char>(text[k + 1]));
        }
    }
    return static_cast<int>(width);
}

} // namespace karamock

measureWidth reprend exactement le calcul d'avancement de drawText, sans jamais rastériser — c'est ce qui permet de centrer "Karamock" dans le cadre de preuve sans dessiner deux fois. font.isValid() vérifié en tête des deux fonctions : si loadFromMemory a échoué (fichier introuvable dans le bundle, .ttf corrompu), drawText ne fait rien plutôt que de déréférencer un stbtt_fontinfo jamais initialisé.

Deux détails qui, oubliés, produisent un rendu silencieusement faux plutôt qu'un crash : iy0 est négatif pour la plupart des lettres (au-dessus de la ligne de base — le bitmap est rangé en y-descendant, l'inverse du sens des contours), donc baselineY + iy0 place bien le haut du glyphe, pas son bas. Et glyphScratch_.assign(...) doit être appelé à chaque glyphe — sans ce reset, les pixels non couverts du glyphe précédent (plus large) restent dans le buffer et se mélangent au suivant.

Une police que le projet a le droit d'embarquer

stb_truetype ne lit que des polices statiques (une graisse = un fichier .ttf) — vérifié dans le code source, aucune table fvar/gvar n'y est gérée, donc une police variable moderne ne fonctionnerait qu'en instance par défaut, sans contrôle. C'est un piège concret à éviter dès le téléchargement : le bouton "Download family" classique de Google Fonts distribue souvent une police variable (un seul fichier pour tous les poids) — stb_truetype ne saurait pas y choisir Regular ou Bold. Police retenue : Noto Sans, en allant chercher directement ses fichiers TTF statiques plutôt que par le téléchargement grand public :

  • Regular : https://raw.githubusercontent.com/notofonts/notofonts.github.io/main/fonts/NotoSans/hinted/ttf/NotoSans-Regular.ttf
  • Bold (facultatif pour cette leçon, utile plus tard pour une ligne active en gras) : https://raw.githubusercontent.com/notofonts/notofonts.github.io/main/fonts/NotoSans/hinted/ttf/NotoSans-Bold.ttf

Même geste que pour stb_truetype.h : ouvrir l'URL, Cmd+S pour enregistrer. Sous licence SIL Open Font License 1.1 — le texte exact se trouve à https://raw.githubusercontent.com/notofonts/latin-greek-cyrillic/main/OFL.txt, à télécharger et embarquer lui aussi (voir plus bas pourquoi). La clause d'autorisation couvre explicitement ce cas d'usage :

"Original or Modified Versions of the Font Software may be bundled, redistributed and/or sold with any software, provided that each copy contains the above copyright notice and this license."

Embarquer NotoSans-Regular.ttf dans l'app, App Store compris, est explicitement autorisé — à une obligation concrète près : livrer une copie de la notice de copyright et du texte de licence avec l'app, exactement le fichier OFL.txt téléchargé ci-dessus (dans le bundle, ou listé sur un écran "Licences" — les licences de logiciels tiers, ça se code aussi, pas juste une formalité à reporter).

Différence importante avec les fichiers .hpp/.cpp vus plus haut : un .ttf n'est pas du code, c'est une ressource. Glisse NotoSans-Regular.ttf et OFL.txt dans le projet (cible Karamock cochée, "Copy items if needed" coché), puis vérifie dans Build Phases → Copy Bundle Resources que les deux y apparaissent — c'est ce qui les rend accessibles au runtime via Bundle.main.url(forResource:withExtension:), pas les Compile Sources utilisées pour le code C++/Swift.

Une confusion possible si tu as déjà embarqué des polices iOS ailleurs : pas besoin de déclarer la police dans Info.plist sous "Fonts provided by application" (UIAppFonts) — cette déclaration sert à enregistrer une police auprès d'UIKit/CoreText pour l'utiliser via UIFont(name:). Ici, rien n'est demandé à UIKit : Swift lit les octets bruts du fichier et les passe directement à Font::loadFromMemory, qui les interprète lui-même via stb_truetype.

Côté Swift : charger la police depuis le bundle, dessiner "Karamock"

// CORRECTION — Views/Discovery/EngineProofView.swift
private static func render(pointSize: CGSize, scale: CGFloat) -> CGImage? {
    let pixelWidth  = Int((pointSize.width  * scale).rounded())
    let pixelHeight = Int((pointSize.height * scale).rounded())

    guard let fontURL = Bundle.main.url(forResource: "NotoSans-Regular", withExtension: "ttf"),
          let fontData = try? Data(contentsOf: fontURL)
    else { return nil }

    var font = karamock.Font()
    let loaded = fontData.withUnsafeBytes { rawBuffer -> Bool in
        guard let base = rawBuffer.bindMemory(to: UInt8.self).baseAddress else { return false }
        return font.loadFromMemory(base, rawBuffer.count)
    }
    guard loaded else { return nil }

    var buffer = karamock.PixelBuffer()
    buffer.resize(Int32(pixelWidth), Int32(pixelHeight))
    buffer.fill(20, 20, 30)   // fond sombre, pour que le texte clair ressorte

    var renderer = karamock.TextRenderer()
    let color = karamock.Color(r: 240, g: 240, b: 245)
    renderer.drawText(&buffer, font, std.string("Karamock"), 20, Int32(pixelHeight / 2), 48, color)

    guard let base = buffer.__dataUnsafe() else { return nil }
    let pixels = Data(bytes: base, count: buffer.sizeInBytes())

    guard let provider = CGDataProvider(data: pixels as CFData),
          let colorSpace = CGColorSpace(name: CGColorSpace.sRGB)
    else { return nil }

    let bitmapInfo = CGBitmapInfo(
        rawValue: CGImageAlphaInfo.premultipliedLast.rawValue
                | CGImageByteOrderInfo.order32Big.rawValue
    )

    return CGImage(
        width: Int(buffer.width()), height: Int(buffer.height()),
        bitsPerComponent: 8, bitsPerPixel: 32, bytesPerRow: Int(buffer.bytesPerRow()),
        space: colorSpace, bitmapInfo: bitmapInfo, provider: provider,
        decode: nil, shouldInterpolate: false, intent: .defaultIntent
    )
}

fontData.withUnsafeBytes { ... } plutôt que Array(fontData) : ce dernier aurait fonctionné, mais en copiant deux fois (une fois de Data vers [UInt8], une seconde fois de [UInt8] vers le std::vector<uint8_t> C++ à la frontière — dont la Leçon 37 a déjà signalé que l'interop ne garantit aucune performance particulière pour ce genre de conversion). withUnsafeBytes donne directement un pointeur dans le buffer déjà détenu par Data, passé tel quel à la seconde surcharge de loadFromMemory — une seule copie au total, celle que Font doit de toute façon faire pour posséder ses propres octets. Sans rapport avec le sujet de performance à chaque frame déjà signalé en Leçon 37 pour la lecture depuis Swift : ici c'est l'inverse, un envoi ponctuel vers le C++, une fois au lancement.

Autre correction à ne pas manquer : baselineY est un int côté C++, donc un Int32 côté Swift — un littéral comme 20 passe directement, mais pixelHeight / 2 (un Int Swift, pas un littéral) a besoin du cast explicite Int32(...), sans quoi le projet ne compile pas. std.string("Karamock") : même cast obligatoire qu'en Leçon 37, une chaîne littérale ne suffit pas à passer un std::string en argument.

// Bridging header

Dans Xcode : ajoute NotoSans-Regular.ttf et OFL.txt au bundle de ressources de la target (glisser dans le projet, cocher "Copy items if needed" et la target Karamock). Le dossier Engine/ThirdParty/ reçoit stb_truetype.h (fichier vendu tel quel, licence comprise) et stb_truetype_impl.cpp.

État réel de l'implémentation (comparé le 8 août 2026) : conforme dans l'ensemble, avec deux écarts corrigés ci-dessus dans la leçon — scaleForPixelHeight renommée scaleForPixelsHeight, et surtout un Int32(pixelHeight / 2) nécessaire pour baselineY que la leçon ne montrait pas (le code ne compilait pas sans ce cast). Une amélioration a aussi été adoptée depuis l'implémentation réelle : le chargement de la police passe par withUnsafeBytes et une surcharge loadFromMemory(const uint8_t*, size_t), plutôt que par Array(fontData) — une copie de moins.
Scénario de vérification, étape par étape :
  1. Vérifie que NotoSans-Regular.ttf et OFL.txt sont bien copiés dans le bundle de l'app (Build Phases → Copy Bundle Resources).
  2. Build (⌘B) sur un simulateur iPhone et un simulateur Apple TV : les deux doivent réussir.
  3. Ouvre l'écran Découvrir : le mot "Karamock" doit apparaître lisible, en clair sur fond sombre, à la place du dégradé/damier de la Leçon 37.
  4. Vérifie que les lettres rondes ("a", "o") ne laissent voir aucun résidu du glyphe précédent superposé (le bug du glyphScratch_ non réinitialisé, si présent, produit des taches visibles entre les lettres).
  5. Compare la netteté du texte entre un simulateur @2x et @3x : doit rester net dans les deux cas, displayScale continue de s'appliquer comme en Leçon 37.
  6. Retire temporairement + 127 de blendPixel pour comparer visuellement l'arrondi vs la troncature sur les bords des lettres, puis remets-le.
