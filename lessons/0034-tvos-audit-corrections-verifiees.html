Leçon 34 · Multi-plateforme (4/N)

Un audit tvOS passé au crible : ce qu'on corrige, ce qu'on refuse

Un audit externe (audits/2026-08-02-tvos-audit.md, 3 agents Copilot spécialisés, note globale 4.2/10) a listé 22 problèmes sur Karamock tvOS. Avant d'en corriger un seul, chaque remarque a été vérifiée contre la doc Apple officielle et contre le code réel — deux des six problèmes "critiques" se sont révélés factuellement faux, un troisième proposait d'annuler le correctif de la Leçon 33. Cette leçon applique les corrections qui ont survécu à la vérification, et documente pourquoi les autres sont refusées.

Le audit, réévalué : 4 sous-agents spécialistes, verdict par verdict

Remarque de l'auditVerdict vérifié
C1 — .sheet() "ignoré silencieusement sur tvOS"🟡 Contredit par le HIG ("a sheet is always modal" sur tvOS — elle s'affiche, juste toujours en plein modal). À confirmer sur device pour le cas précis .sheet(item:) déclenché depuis une liste.

Pourquoi C6/I9 ne sont pas traités ici, alors qu'ils sont bien réels

Les boutons précédent/suivant vides et les manques de PlayerState existent sur iOS comme sur tvOS — ce n'est pas un problème de plateforme, c'est une fonctionnalité jamais construite. Les corriger demanderait d'ajouter playlist, currentIndex, playNext(), playPrevious() à PlayerState : un vrai morceau de travail produit, pas un correctif tvOS. L'audit est un instantané utile, pas une spécification à exécuter telle quelle — ce point reste noté pour une leçon dédiée, si Nicolas le demande, plutôt que traité en douce ici.

Corrections adoptées

État réel de l'implémentation (comparé le 2026-08-03, mis à jour après la Leçon 35) : 7 des 10 correctifs ci-dessous sont déjà appliqués par Nicolas — .onPlayPauseCommand (les deux fichiers), .focusSection(), les labels de temps, les tailles PlaylistCard/SongRow/SongHeader, l'espacement de SongOptionsForm, StretchyView, et .refreshable. Trois ne le sont pas encore, par simple omission — le code enseigné plus bas reste correct, juste pas encore recopié dans le projet : les labels d'accessibilité paramétrés et l'agrandissement des boutons de FocusStepperTV (section 4), la hauteur tvOS de PlaylistCoverHeader (section 5, dernière ligne du tableau), et .focusable() sur LyricsView (aside en fin de section). Un vrai correctif restait nécessaire dans le contenu ci-dessous : le code .onPlayPauseCommand de la section 1 manquait une garde #if os(tvOS), ce qui cassait la compilation iOS — repéré et corrigé par Nicolas pendant la Leçon 35 (build croisé iOS/tvOS), et corrigé ici en conséquence.

1. Télécommande Siri Remote — .onPlayPauseCommand

Vrai manque confirmé : aucun handler pour le bouton physique Play/Pause. Point notable au-delà du simple "il en manque un" : c'est une commande télécommande globale, pas un second Button focusable — elle donne à MiniPlayerBarTV un contrôle play/pause sans violer la règle "un seul élément focusable par composant" décidée en Leçon 32 (c'est précisément pour cette raison que MiniPlayerBarTV n'avait pas de bouton play/pause dédié jusqu'ici).

// FullScreenPlayerView.swift — sur le VStack principal
.padding()
#if os(tvOS)
.onPlayPauseCommand { player.isPlaying.toggle() }
#endif

// MiniPlayerBarTV.swift — sur le Button
.buttonStyle(.plain)
#if os(tvOS)
.onPlayPauseCommand { player.isPlaying.toggle() }
#endif

Correction (2026-08-03) : le code enseigné ici manquait à l'origine la garde #if os(tvOS). Comme FullScreenPlayerView.swift et MiniPlayerBarTV.swift compilent pour les deux destinations (mécanisme de la Leçon 31, pas de séparation de target), un appel .onPlayPauseCommand non gardé — API tvOS 13+ exclusive — casse la compilation côté iOS. Ce n'était pas visible tant que seule la destination tvOS était buildée ; le bug a été repéré et corrigé par Nicolas pendant la Leçon 35, à l'étape de son scénario de vérification qui impose un build iOS et tvOS.

2. Focus Engine — .focusSection() sur l'overlay mini-lecteur

Confirmé tvOS 15+ : guide le Focus Engine pour qu'il atteigne correctement une zone d'overlay (comme MiniPlayerBarTV, posée par-dessus le TabView plutôt qu'intégrée à sa hiérarchie normale).

// RootTabView.swift
.overlay(alignment: .bottom) {
    if let song = player.currentSong, !player.isExpanded {
        MiniPlayerBarTV(song: song)
            .padding(.horizontal, 60)
            .padding(.bottom, 40)
            .focusSection()
    }
}

3. Labels de temps figés (bug général, corrigé au passage)

Confirmé en lisant le fichier : Text("0:00") est un texte en dur, jamais mis à jour. Un helper formatTime(_:) existe déjà dans Views/Common/TimeFormatter.swift — pas besoin d'en écrire un nouveau.

// FullScreenPlayerView.swift
HStack {
    Text(formatTime(progress))
    Spacer()
    Text("-" + formatTime(song.durationInSeconds - progress))
}
.font(.caption)
.foregroundStyle(.secondary)

4. Labels d'accessibilité de FocusStepperTV — paramétrés, pas codés en dur

L'audit proposait de remplacer "Diminuer"/"Augmenter" par "Reculer de 10s"/"Avancer de 10s" (M6) — un correctif faux par excès de généralisation : FocusStepperTV est un composant partagé entre trois contextes (tonalité, tempo, progression), et "reculer de 10s" n'a aucun sens pour un réglage de tonalité. Le vrai correctif est de paramétrer les labels, pas de les figer sur un seul usage :

// FocusStepperTV.swift
struct FocusStepperTV: View {
    let onDecrement: () -> Void
    let onIncrement: () -> Void
    var decrementDisabled = false
    var incrementDisabled = false
    var decrementLabel = "Diminuer"
    var incrementLabel = "Augmenter"

    var body: some View {
        HStack(spacing: 24) {
            Button(action: onDecrement) {
                Image(systemName: "minus.circle.fill")
            }
            .disabled(decrementDisabled)
            .accessibilityLabel(decrementLabel)

            Button(action: onIncrement) {
                Image(systemName: "plus.circle.fill")
            }
            .disabled(incrementDisabled)
            .accessibilityLabel(incrementLabel)
        }
        #if os(tvOS)
        .font(.system(size: 40))
        #else
        .font(.title2)
        #endif
        .buttonStyle(.plain)
    }
}

Les valeurs par défaut ("Diminuer"/"Augmenter") restent correctes pour tonalité et tempo — seul l'appel de FullScreenPlayerView pour la progression a besoin de labels spécifiques :

// FullScreenPlayerView.swift
FocusStepperTV(
    onDecrement: { progress = max(0, progress - 10) },
    onIncrement: { progress = min(song.durationInSeconds, progress + 10) },
    decrementDisabled: progress <= 0,
    incrementDisabled: progress >= song.durationInSeconds,
    decrementLabel: "Reculer de 10 secondes",
    incrementLabel: "Avancer de 10 secondes"
)

Sur la taille : l'audit suggérait frame(width: 80, height: 80) sur les boutons. Écarté au profit d'une police plus grande (.system(size: 40)) — ce sont des icônes SF Symbols sans fond ni bordure ; un frame invisible autour d'une petite icône ajoute de l'espace vide autour d'elle, une police plus grande agrandit réellement ce qui est visible à l'écran.

6. StretchyView désactivée sur tvOS

Le geste de scroll tvOS (surface tactile de la télécommande, discret) rend l'effet d'étirement peu pertinent — actuellement appliqué sans condition de plateforme :

// StretchyView.swift
extension View {
    func stretchy() -> some View {
        #if os(iOS)
        visualEffect { effect, geometry in
            let currentHeight = geometry.size.height
            let scrollOffset = geometry.frame(in: .scrollView).minY
            let positiveOffset = max(0, scrollOffset)
            let scaleFactor = (currentHeight + positiveOffset) / currentHeight
            return effect.scaleEffect(x: scaleFactor, y: scaleFactor, anchor: .bottom)
        }
        #else
        self
        #endif
    }
}

7. .refreshable retiré sur tvOS

Confirmé disponible tvOS 15+ (ne casse rien, contrairement à ce qu'aurait pu laisser croire une lecture rapide de l'audit) — mais sa doc officielle ne décrit le geste "tirer pour rafraîchir" que pour iOS/iPadOS. Sur tvOS, ce geste n'a pas d'équivalent télécommande : le modificateur ne fait rien de mal, il est juste mort. Retiré pour ne pas laisser du code qui ne peut jamais se déclencher :

// LibraryView.swift
#if os(iOS)
.refreshable { await viewModel.refresh() }
#endif
Correctif tenté mais non garanti : .focusable() sur LyricsView

L'audit signale que le ScrollView des paroles ne reçoit pas le focus sur tvOS, empêchant la navigation manuelle dedans (I2) — plausible, puisqu'il ne contient que des Text, aucun élément focusable. Recherche menée avant d'écrire cette leçon : aucune documentation officielle Apple ne confirme que .focusable() active réellement le défilement par swipe sur une ScrollView — seulement qu'il en fait une cible de focus. Appliqué quand même, à titre d'essai documenté :

// LyricsView.swift
ScrollView {
    ...
}
#if os(tvOS)
.focusable()
#endif

À vérifier concrètement une fois buildé : le défilement manuel des paroles fonctionne-t-il réellement, ou seul le défilement automatique (piloté par currentTime) reste actif ? Si .focusable() seul ne suffit pas, ce sera le sujet d'une leçon dédiée plutôt qu'une hypothèse non vérifiée de plus.

Scénario de vérification, étape par étape :
  1. Build (⌘B) sur le simulateur Apple TV et sur un simulateur iPhone : les deux doivent réussir, aucun changement de rendu attendu sur iOS.
  2. Sur le simulateur Apple TV (Hardware → touche Play/Pause, ou raccourci équivalent) : vérifie que la lecture bascule play/pause depuis le lecteur plein écran ET depuis le mini-lecteur, sans qu'aucun des deux n'ait le focus.
  3. Vérifie que le focus atteint bien MiniPlayerBarTV en naviguant vers le bas depuis les onglets.
  4. Ouvre le lecteur plein écran : les temps affichés ("0:12", "-2:45"...) doivent maintenant évoluer avec la lecture, plus jamais "0:00" figé.
  5. Sur les réglages de tonalité/tempo/progression, active VoiceOver (Apple TV Remote app ou simulateur) et vérifie que les labels lus sont différents selon le contexte (tonalité/tempo vs "Reculer de 10 secondes").
  6. Compare visuellement les cartes de playlist, les lignes de chanson et l'en-tête de playlist entre iPhone et Apple TV : les éléments doivent être nettement plus grands sur tvOS, sans rien casser sur iOS.
  7. Dans les paroles du lecteur plein écran, essaie de faire défiler manuellement avec la télécommande : note si ça fonctionne réellement (point non garanti signalé plus haut).
  8. Dans la Bibliothèque sur tvOS, vérifie qu'aucun geste "tirer pour rafraîchir" n'est proposé ni ne bloque quoi que ce soit.
