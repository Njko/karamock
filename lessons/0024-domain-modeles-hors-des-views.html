Leçon 24 · Nettoyage architecture (1/N)

Le Domain a besoin d'un vrai chez-lui

L'audit Clean Architecture du 28 juillet (audits/2026-07-28-clean-architecture-audit.md) note le Domain à 4.5/10 : "quasi-vide — entités métier dispersées dans Views/". Cette leçon ouvre un court arc dédié à résoudre ce que l'audit a remonté, dans l'ordre du risque le plus faible au plus élevé. On commence par le plus sûr : déplacer des fichiers, sans changer une seule ligne de logique.

Pourquoi cette leçon : la mission prévoyait une architecture en couches introduite "pour être capable de discuter de structuration d'app à un niveau Tech Lead". Réagir à un audit externe — trier ce qui est vraiment un risque de ce qui est cosmétique, corriger dans le bon ordre — est exactement ce réflexe-là en action, pas une leçon de plus sur la théorie des couches.

Ce que l'audit a trouvé

Trois constats précis, tous vérifiés dans le code actuel :

  • Les entités métier vivent dans Views/ — Song, LyricsLine, KaraokeMode dans Views/Common/Model/, Playlist dans Views/Player/Model/, LyricsError dans Services/. Le dossier Domain/ ne contient à ce jour que DownloadState et les UseCase.
  • Playlist importe SwiftUI — let gradientColors: [Color] couple une entité métier au framework d'UI. Impossible de tester ou de réutiliser ce type sans importer SwiftUI avec lui.
  • La couche Data dépend de la couche Views — CachedLyricsRepository (Data) utilise song.durationInSeconds, défini dans Views/Common/TimeUtilities.swift. Le sens de dépendance correct est Data → Domain, jamais Data → Views.

Aucun de ces trois points ne change le comportement de l'app — ce sont des questions d'organisation et de direction de dépendance, pas des bugs. C'est justement pour ça qu'on commence ici : le risque de casser quelque chose est proche de zéro, et ça prépare le terrain pour les leçons suivantes de cet arc, qui toucheront à du vrai comportement.

Déplacer les entités, sans rien changer d'autre

Quatre fichiers changent simplement de dossier — contenu identique :

LyricsLine.swift contient aussi mockLyrics — on ne le touche pas ici

let mockLyrics: [LyricsLine] = [...] est une donnée de test qui vit dans le bundle de production — c'est un problème distinct, déjà repéré par l'audit (point #9), qui sera traité dans une leçon dédiée au nettoyage du code de test hors du bundle prod. Le déplacer maintenant, en même temps que la struct LyricsLine, mélangerait deux sujets dans une leçon censée rester "juste un déplacement de fichiers".

Playlist : sortir Color du Domain

Ce cas est le seul des quatre qui touche vraiment à du code, pas juste à un emplacement de fichier :

// AVANT — Views/Player/Model/Playlist.swift
import Foundation
import SwiftUI

struct Playlist: Identifiable, Hashable {
    let id = UUID()
    let title: String
    let gradientColors: [Color]
    let songs: [Song]
}
// APRÈS — Domain/Models/Playlist.swift
import Foundation

struct Playlist: Identifiable, Hashable {
    let id = UUID()
    let title: String
    let songs: [Song]
}

gradientColors n'est pas une donnée métier — Playlist n'a pas besoin de savoir qu'elle a une couleur pour exister. C'est un détail de présentation, qui doit vivre côté vue :

// NOUVEAU — Views/Player/Model/Playlist+GradientColors.swift
import SwiftUI

extension Playlist {
    var gradientColors: [Color] {
        switch title {
        case "Best Of Rock":
            return [.red, .orange]
        case "Années 2000\nen France":
            return [.blue, .green]
        case "Karaoké\nClassics":
            return [.yellow, .purple]
        default:
            return [.gray]
        }
    }
}

PlaylistCard et PlaylistCoverHeader ne changent pas une ligne : ils lisent playlist.gradientColors exactement comme avant — c'est toujours une propriété calculée sur Playlist, juste définie dans une extension côté Views/ plutôt que comme propriété stockée sur le type lui-même. Seul MockPlaylist.swift change, en retirant l'argument devenu inutile :

// MockPlaylist.swift — avant
Playlist(title: "Best Of Rock", gradientColors: [.red, .orange], songs: [ ... ])

// MockPlaylist.swift — après
Playlist(title: "Best Of Rock", songs: [ ... ])
Faire correspondre sur title est un compromis, pas une solution définitive

Un switch sur une chaîne de caractères est fragile : une faute de frappe dans un futur titre de playlist tombe silencieusement dans default, sans avertissement. C'est un compromis honnête ici, pas une bonne pratique à généraliser — la vraie solution demanderait un identifiant stable et dédié pour associer une playlist à son thème visuel, plutôt que son titre affiché. Rien de plus robuste n'est proposé pour l'instant : Playlist.id est un UUID() régénéré à chaque lancement, donc pas plus fiable que title pour cet usage — même souci d'identité instable que Song.id, que l'audit signale aussi et qu'une prochaine leçon de cet arc corrigera.

TimeUtilities : scinder en deux, selon qui en a besoin

Views/Common/TimeUtilities.swift mélangeait une extension de domaine (durationInSeconds, utilisée par CachedLyricsRepository en couche Data) et une fonction de présentation (formatTime, qui formate un TimeInterval en chaîne "MM:SS" pour l'affichage). Les séparer élimine la dépendance Data → Views identifiée par l'audit :

// NOUVEAU — Domain/Extensions/Song+Duration.swift
import Foundation

extension Song {
    nonisolated var durationInSeconds: TimeInterval {
        let parts = duration.split(separator: ":").compactMap { Double($0) }
        guard parts.count == 2 else { return 0 }
        return parts[0] * 60 + parts[1]
    }
}
// NOUVEAU — Views/Common/TimeFormatter.swift
import Foundation

func formatTime(_ seconds: TimeInterval) -> String {
    let total = Int(seconds)
    return String(format: "%02d:%02d", total / 60, total % 60)
}

Views/Common/TimeUtilities.swift disparaît, remplacé par ces deux fichiers. CachedLyricsRepository (Data) dépend maintenant de Domain/Extensions/Song+Duration.swift (Domain) — Data → Domain, le seul sens autorisé. FullScreenPlayerView continue d'utiliser song.durationInSeconds sans rien changer, Presentation → Domain étant tout aussi correct.

En creusant : formatTime ne semble appelé nulle part actuellement

Une recherche dans tout Sources/Karamock/ ne trouve aucun appel à formatTime — la fonction existe mais n'est branchée sur aucun écran. Rien à voir avec le sujet de cette leçon ni avec un point de l'audit ; à garder en tête pour une passe de nettoyage future (soit la brancher quelque part, soit la retirer si elle est vraiment inutile).

Scénario de vérification, étape par étape :
  1. Build du projet (⌘B) : doit réussir sans erreur ni avertissement nouveau — c'est un pur déplacement, rien ne doit casser la compilation.
  2. Onglet "Découvrir" : les trois playlists mock doivent garder exactement leurs couleurs actuelles (Best Of Rock en rouge/orange, Années 2000 en bleu/vert, Karaoké Classics en jaune/violet) — aucun changement visuel attendu.
  3. Ouvre une chanson et lance la lecture : le Slider de progression et le lecteur plein écran doivent se comporter exactement comme avant (durée totale correcte, décompte qui avance).
