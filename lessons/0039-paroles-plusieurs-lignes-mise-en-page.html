Leçon 39 · Moteur de paroles en C++ (3/N)

Les vraies paroles, plusieurs lignes, mise en page

La Leçon 36 a envoyé la collection de paroles horodatées vers LyricsStore. Les Leçons 37 et 38 ont prouvé que le C++ peut dessiner du texte lisible dans le buffer. Aucune de ces trois briques ne parle encore à l'autre : LyricsStore ne sait pas rendre ce qu'il contient, et TextRenderer ne dessine qu'une seule ligne fixe, choisie à la main. Cette leçon les assemble : trouver la ligne active pour un instant donné, puis afficher plusieurs lignes centrées, la ligne en cours mise en avant, celles d'avant et d'après en retrait — la mise en page qu'on reconnaît dans un karaoké. Toujours pas d'animation ni de défilement fluide : c'est un instantané, à un currentTime fixe. Le mouvement viendra dans une leçon dédiée.

LyricsStore ne sait encore que compter et dater

Relire ce que LyricsStore expose depuis la Leçon 36 :

// Engine/LyricsStore.hpp — état avant cette leçon
std::size_t lineCount() const;
double timeAt(std::size_t index) const;

addLine(time, text) pousse une ligne dedans, mais rien ne permet de la relire : timeAt redonne l'horodatage, jamais le texte. Le test de la Leçon 36 (assert(lyricsStore.lineCount() == lyrics.count)) vérifiait que les paroles étaient bien arrivées côté C++ — pas qu'on pouvait s'en resservir pour les afficher. C'est le trou à combler en premier, avant même de parler de mise en page :

// CORRECTION — Engine/LyricsStore.hpp
#pragma once
#include <cstddef>
#include <string>
#include <vector>

namespace karamock {

struct LyricLine {
    double time;
    std::string text;
};

class LyricsStore {
public:
    static constexpr std::size_t npos = static_cast<std::size_t>(-1);   // NOUVEAU

    LyricsStore() = default;
    void reserve(std::size_t count);
    void addLine(double time, const std::string& text);   // précondition : appelée avec des `time` croissants
    void clear();

    std::size_t lineCount() const;
    double timeAt(std::size_t index) const;
    const std::string& textAt(std::size_t index) const;   // NOUVEAU

    std::size_t indexAtTime(double time) const;   // NOUVEAU — npos si aucune ligne n'est encore active
private:
    std::vector<LyricLine> lines_;
};

} // namespace karamock

npos reprend délibérément le nom et la convention de std::string::npos : un sentinel du même type que l'index qu'il représente (std::size_t), plutôt qu'un int signé à -1 qui obligerait à un cast à chaque comparaison, ou un std::optional<std::size_t> qui ajouterait une indirection pour un cas que la bibliothèque standard résout déjà par convention.

Trouver la ligne active : indexAtTime

indexAtTime répond à une question précise : "à cet instant, quelle est la dernière ligne dont l'horodatage est déjà passé ?" C'est exactement ce que std::upper_bound calcule — à condition que les lignes soient triées par time croissant, ce que addLine suppose sans jamais le vérifier lui-même jusqu'ici :

// CORRECTION — Engine/LyricsStore.cpp
#include "LyricsStore.hpp"
#include <algorithm>
#include <cassert>

namespace karamock {

void LyricsStore::reserve(std::size_t count) {
    lines_.reserve(count);
}

void LyricsStore::addLine(double time, const std::string &text) {
    assert(lines_.empty() || time >= lines_.back().time);   // NOUVEAU — indexAtTime suppose l'ordre croissant
    lines_.push_back(LyricLine{time, text});
}

void LyricsStore::clear() {
    lines_.clear();
}

std::size_t LyricsStore::lineCount() const {
    return lines_.size();
}

double LyricsStore::timeAt(std::size_t index) const {
    return lines_[index].time;
}

const std::string& LyricsStore::textAt(std::size_t index) const {   // NOUVEAU
    return lines_[index].text;
}

std::size_t LyricsStore::indexAtTime(double time) const {   // NOUVEAU
    if (lines_.empty() || time < lines_.front().time) {
        return npos;
    }
    const auto it = std::upper_bound(lines_.begin(), lines_.end(), time,
        [](double t, const LyricLine& line) { return t < line.time; });
    return static_cast<std::size_t>(it - lines_.begin() - 1);
}

} // namespace karamock

Deux gardes-fous distincts, à ne pas confondre. L'assert dans addLine est une vérification en écriture — elle protège la précondition d'indexAtTime le plus tôt possible, au moment où une ligne mal ordonnée est ajoutée, plutôt que de laisser un résultat silencieusement faux apparaître bien plus tard à l'affichage. La garde time < lines_.front().time dans indexAtTime est une vérification en lecture : sans elle, demander l'index actif avant que la première ligne n'ait commencé renverrait 0 — une ligne "active" avant même son propre horodatage, un bug silencieux plutôt qu'un crash. upper_bound retourne un itérateur sur la première ligne dont le time dépasse strictement l'instant cherché ; reculer d'un cran (- 1) donne la dernière ligne déjà commencée, exactement la définition de "ligne active".

LyricsPage : le moteur décide qui afficher, où, et comment

Une nouvelle classe compose les trois briques existantes plutôt que d'ajouter cette logique dans TextRenderer (qui ne doit rien savoir des paroles) ou dans LyricsStore (qui ne doit rien savoir du dessin) :

// NOUVEAU — Engine/LyricsPage.hpp
#pragma once

namespace karamock {

class Font;
class PixelBuffer;
class TextRenderer;
class LyricsStore;

class LyricsPage {
public:
    void render(PixelBuffer& target, const Font& font, TextRenderer& renderer,
                const LyricsStore& lyrics, double currentTime) const;
};

} // namespace karamock
// NOUVEAU — Engine/LyricsPage.cpp
#include "LyricsPage.hpp"
#include "Font.hpp"
#include "PixelBuffer.hpp"
#include "TextRenderer.hpp"
#include "LyricsStore.hpp"

namespace karamock {

namespace {

Color dim(Color c) {
    return Color{
        static_cast<std::uint8_t>(c.r / 3),
        static_cast<std::uint8_t>(c.g / 3),
        static_cast<std::uint8_t>(c.b / 3)
    };
}

void drawCentered(PixelBuffer& target, const Font& font, TextRenderer& renderer,
                   const std::string& text, int baselineY, float pixelHeight, Color color) {
    const int width = renderer.measureWidth(font, text, pixelHeight);
    const int x = (target.width() - width) / 2;
    renderer.drawText(target, font, text, x, baselineY, pixelHeight, color);
}

} // namespace

void LyricsPage::render(PixelBuffer& target, const Font& font, TextRenderer& renderer,
                         const LyricsStore& lyrics, double currentTime) const {
    const std::size_t active = lyrics.indexAtTime(currentTime);
    if (active == LyricsStore::npos) {
        return;   // rien avant la première ligne
    }

    constexpr float activeHeight = 56.0f;
    constexpr float sideHeight = 32.0f;
    const Color activeColor{240, 240, 245};
    const Color sideColor = dim(activeColor);

    int ascent = 0, descent = 0, lineGap = 0;
    font.verticalMetrics(&ascent, &descent, &lineGap);
    const float lineAdvance = (ascent - descent + lineGap) * font.scaleForPixelsHeight(activeHeight);

    const int centerY = target.height() / 2;
    drawCentered(target, font, renderer, lyrics.textAt(active), centerY, activeHeight, activeColor);

    if (active > 0) {
        drawCentered(target, font, renderer, lyrics.textAt(active - 1),
                     centerY - static_cast<int>(lineAdvance), sideHeight, sideColor);
    }
    if (active + 1 < lyrics.lineCount()) {
        drawCentered(target, font, renderer, lyrics.textAt(active + 1),
                     centerY + static_cast<int>(lineAdvance), sideHeight, sideColor);
    }
}

} // namespace karamock

Font::verticalMetrics existe depuis la Leçon 38 mais n'y était jamais appelée — elle sert enfin ici : ascent - descent + lineGap est la distance verticale standard entre deux lignes de base consécutives dans une police, mise à l'échelle par scaleForPixelsHeight comme n'importe quelle autre mesure de la police. Un écart fixe en pixels aurait fonctionné pour une seule combinaison de tailles, mais serait devenu trop serré ou trop large dès que activeHeight ou sideHeight changerait — ce calcul s'adapte à la police et à la taille réellement utilisées, pas à une valeur choisie à l'œil pour ce cas précis.

drawCentered appelle measureWidth avant drawText, jamais l'inverse : la position x de départ dépend de la largeur totale du texte, connue seulement une fois tous les glyphes parcourus. measureWidth refait ce même calcul d'avancement sans rastériser un seul pixel (établi en Leçon 38) — le prix de ce double parcours est un calcul de plus par ligne, pas un dessin de plus.

Ligne courante en TextRenderer& non-const, LyricsStore en const& : TextRenderer mute glyphScratch_, son buffer de travail interne, à chaque glyphe dessiné — un état réel qui change. LyricsStore n'est jamais modifié pendant le rendu, seulement lu via textAt, indexAtTime et lineCount ; la const& documente cette garantie autant qu'elle l'impose.

Si la ligne active n'existe pas encore (active == 0, pas de ligne précédente) ou si elle est la dernière (pas de ligne suivante), les deux if l'excluent proprement plutôt que de tenter textAt(active - 1) avec un index qui, en arithmétique non signée, "déborderait" vers une valeur énorme au lieu de devenir négatif.

Côté Swift : des paroles de test, plusieurs lignes, un instant choisi

// CORRECTION — Views/Discovery/EngineProofView.swift
struct EngineProofView: View {
    @Environment(\.displayScale) private var displayScale
    @State private var image: CGImage?

    private let pointSize = CGSize(width: 320, height: 200)   // agrandi : trois lignes, plus une seule

    // ... body inchangé depuis la Leçon 38 ...

    private static func render(pointSize: CGSize, scale: CGFloat) -> CGImage? {
        let pixelWidth  = Int((pointSize.width  * scale).rounded())
        let pixelHeight = Int((pointSize.height * scale).rounded())

        guard let fontURL = Bundle.main.url(forResource: "NotoSans-Regular", withExtension: "ttf"),
              let fontData = try? Data(contentsOf: fontURL)
        else { return nil }

        var font = karamock.Font()
        guard loadFont(from: fontData, into: &font) else { return nil }

        var buffer = karamock.PixelBuffer()
        buffer.resize(Int32(pixelWidth), Int32(pixelHeight))
        buffer.fill(20, 20, 30)

        var lyricsStore = karamock.LyricsStore()
        let testLines: [(time: Double, text: String)] = [
            (0.0, "Premiere ligne, deja terminee"),
            (2.0, "Deuxieme ligne, celle qui joue maintenant"),
            (4.0, "Troisieme ligne, pas encore arrivee")
        ]
        lyricsStore.reserve(testLines.count)
        for line in testLines {
            lyricsStore.addLine(line.time, std.string(line.text))
        }

        var renderer = karamock.TextRenderer()
        let page = karamock.LyricsPage()
        page.render(&buffer, font, &renderer, lyricsStore, 2.5)   // entre la 2e et la 3e ligne : la 2e est active

        guard let base = buffer.__dataUnsafe() else { return nil }
        let pixels = Data(bytes: base, count: buffer.sizeInBytes())

        guard let provider = CGDataProvider(data: pixels as CFData),
              let colorSpace = CGColorSpace(name: CGColorSpace.sRGB)
        else { return nil }

        let bitmapInfo = CGBitmapInfo(
            rawValue: CGImageAlphaInfo.premultipliedLast.rawValue
                    | CGImageByteOrderInfo.order32Big.rawValue
        )

        return CGImage(
            width: Int(buffer.width()), height: Int(buffer.height()),
            bitsPerComponent: 8, bitsPerPixel: 32, bytesPerRow: Int(buffer.bytesPerRow()),
            space: colorSpace, bitmapInfo: bitmapInfo, provider: provider,
            decode: nil, shouldInterpolate: false, intent: .defaultIntent
        )
    }

    private static func loadFont(from data: Data, into font: inout karamock.Font) -> Bool {
        data.withUnsafeBytes { rawBuffer in
            guard let baseAddress = rawBuffer.bindMemory(to: UInt8.self).baseAddress else {
                return false
            }
            return font.loadFromMemory(baseAddress, rawBuffer.count)
        }
    }
}

2.5 passé directement, sans cast, à un paramètre C++ double currentTime : contrairement à baselineY (Int32) en Leçon 38, un Double Swift correspond directement au double C++ des deux côtés de l'interop, littéral ou non — line.time, une propriété Double non littérale, traverse déjà la frontière sans cast dans FullScreenPlayerViewModel.sendLyricsToEngine() depuis la Leçon 36. Rien à ajouter ici, seulement à remarquer que ce n'est pas systématique : la règle du cast explicite ne s'applique qu'aux types entiers de largeur fixe comme Int/Int32, pas aux types à virgule flottante.

Les trois lignes de test évitent volontairement tout accent (é, è, à) — pas un hasard. TextRenderer::drawText itère text[k] comme un octet unique (static_cast<unsigned char>) et traite text.size() comme un nombre de glyphes. Un caractère accentué encodé en UTF-8 tient sur plusieurs octets : chacun serait rastérisé séparément comme un glyphe invalide, produisant un résultat visuellement cassé plutôt qu'un crash. Un vrai problème pour un karaoké en français, volontairement laissé de côté : le moteur ne gère aujourd'hui que de l'ASCII, l'Unicode viendra dans une leçon dédiée plutôt que d'être traité en passant ici.

La ligne active s'affiche bien mais déborde du cadre sur les bords gauche ou droit avec un texte de test plus long ? C'est attendu pour l'instant : LyricsPage centre le texte mais ne le découpe jamais s'il dépasse la largeur du buffer — blendPixel le protège d'un crash (les pixels hors bornes sont simplement ignorés, établi en Leçon 38), mais rien ne raccourcit ou ne redimensionne la ligne.
